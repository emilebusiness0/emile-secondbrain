**Netlify Forms gotcha this surfaced — important if the site is ever redeployed to a *new* Netlify site:** Netlify detects/registers a form by scanning for `data-netlify="true"` **at deploy time**. The 3 forms above no longer have that attribute in source, which is fine for continuing to deploy to the *same, already-registered* Netlify site (forms stay registered once seen, even after the attribute is later removed) — but if this repo is ever deployed fresh to a **different** Netlify site, those 3 forms will silently fail to register/submit until `data-netlify="true"` is temporarily added back for one deploy, then can be removed again to match live's current markup.

**Also verified, not a bug:** HTTP response headers differ between local (`npm run dev`) and live (Netlify's CDN: `server: Netlify`, `cache-status`, `strict-transport-security`, etc.) — expected, since those come from Netlify's edge/platform layer at deploy time, not from anything in the source files. `netlify.toml`'s only custom rule is 1-year immutable caching for `.jpg/.png/.webp`, already correctly configured, nothing to change.

## Multi-step conversational quote form (built + verified 2026-09-02)

Replaced the old single-page ~6-field quote form with a 3-step, one-question-at-a-time flow across all 4 real quote-form pages (`index.html` FR home, `public/soumission/index.html` FR dedicated, `public/en/index.html` EN home, `public/free-quote/index.html` EN dedicated). Referral forms (`programme-reference`/`-en`) untouched except a `data-netlify` fix (see below).

**Field changes (a real scope decision, not just a UI reskin):** email, service type, message, and photo are all dropped entirely from the form - not hidden, removed from the HTML. Duo Vert operates phone-first (email asked for later only if a client wants it), does essentially one core service (specifics asked live during the quote visit), and message/photo weren't worth the friction. Down to 3 real questions: **Zone** (tap one of 6 areas: Gatineau, Aylmer, Hull, Masson-Angers, Buckingham, Ottawa - replaces the old free-text exact address, submitted under the same `name="adresse"` so the Sheet/CRM stay compatible with zero backend changes), **Name**, **Phone**. The CRM's `extractFields()` already treated every field as optional/nullable, confirmed by reading the code directly - no CRM change needed.

**Why dropping the exact address is safe:** the plan for an eventual AI phone-assistant feature (calls new leads back instantly, per the speed-to-lead research from earlier the same day - see [[personal/agency-idea]]) is what the real address collection defers to. Not built yet, just designed to not conflict with it.

**Technical approach:** Netlify Forms detects fields by parsing static HTML at build time, so every real `<input>` stays physically present in the page source exactly as before - the step UI is a pure CSS/JS visibility layer on top (`.fs-step`/`.fs-step-active` class toggle), the underlying `<form>` still POSTs the complete field set on submit. Two new shared files (`public/quote-form.css`, `public/quote-form.js`) referenced from all 4 pages instead of the old full-duplication pattern - real de-duplication, and Vite just copies `public/` verbatim so no build step was needed to make this work. No framework introduced (confirmed the site's React/Tailwind/Framer-Motion-successor packages are dead scaffolding, never wired into any live page - stayed vanilla JS/CSS matching how the rest of the site actually works).

**Motion design** followed the `emil-design-eng` skill's framework rather than arbitrary values: purpose-specific easing curves, asymmetric enter/exit timing (exits faster than entrances), auto-advance on the zone step (tap-and-go, no explicit "Suivant" needed), a star-lighting "pop" animation with a subtle overshoot curve, everything respecting `prefers-reduced-motion`.

**Mobile-specific work:** 16px font-size on typed inputs (iOS auto-zoom prevention), `inputmode="tel"`/`autocomplete` on phone/name for faster mobile entry, popup built as a true bottom sheet with `env(safe-area-inset-bottom)` padding, hover effects gated behind `@media (hover: hover)` so touch doesn't get stuck hover states.

**Popup ("100% sans engagement", ~25s delay, sessionStorage-dismissed) only added to the two homepages**, not the two dedicated quote-form pages - a popup nudging someone toward a form they're already on is redundant. CTA scrolls to `#contact-site` (the existing section id, confirmed by reading the file rather than assumed) instead of a second embedded form, which would've either double-registered fields with Netlify or required a JS-injected form invisible to its static parser.

**Netlify attribute fix:** the 3 FR forms (`soumission-accueil`, `soumission-gratuite`, `programme-reference`) were missing `data-netlify="true"`/`netlify-honeypot="bot-field"` while the EN forms had both - restored uniformly.
